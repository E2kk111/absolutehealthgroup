## Runtime model
**AION™** = intelligence + authority.  
**PolicyPulse™** = policy lifecycle intelligence.  
**RegOS™** = approved regulatory control plane.  
**GitHealth™** = governed execution + economic metering.  
**ShieldAI™** = evidence integrity.  
**Prove™** = evidence + provenance.  
**Economics™** = Workflow Units, Cost-to-Goal™, margin and ROI.

## Runtime loop
**GitHealth context/evidence → AION authority → RegOS executable controls → GitHealth execution → Prove → Economics → outcomes → new context**

## Economic object
A **GitHealth Workflow Unit™** is one completed governed healthcare workflow with defined inputs, evidence requirements, authority controls, execution steps and completion criteria.

WU-1 Eligibility / Rule Check  
WU-2 Documentation Validation  
WU-3 Reimbursement / Evidence Packet  
WU-4 Investigation / Reconciliation  
WU-5 Longitudinal Governed Episode

## Commercial contract stack
**Implementation → Platform Capacity → Included Workflow Units → Overage Workflow Units → Complex Workflow Classes → FDE / Integrations → Prove / Economics Premium**

## National wedges
**CJR-X Recovery-in-a-Box™** = national health-system / orthopedic episode wedge.  
**Precision Recovery Health™ / LTACH OS™** = complex-recovery hospital wedge and deepest AION institutional demonstration.

## Brand rule
New capabilities become modules, controls, Workflow Units or applications by default. Do not create a new top-level brand unless there is a distinct buyer and purchasing decision.
