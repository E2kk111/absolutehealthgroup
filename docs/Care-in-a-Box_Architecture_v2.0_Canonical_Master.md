## 2. AION / GitHealth Operating Loop

AION remains above GitHealth conceptually because AION is the intelligence and authority architecture while GitHealth is the execution substrate.

Operationally:

**GitHealth Context + Evidence → AION Authority → RegOS Controls → GitHealth Execution → Prove → Economics → Outcomes → New Context**

PolicyPulse may discover proposed or future policy, but discovery does not create production authority. Regulatory objects should move through:

**PROPOSED → FINAL / FUTURE EFFECTIVE → ACTIVE → SUPERSEDED → RETIRED**

## 3. Commercial Principle

**Care-in-a-Box™ is what the customer buys.**

The commercial package may include software, clinical workflow, implementation, training, measurement, evidence and economics. The customer does not buy tokens, model calls, knowledge graphs or MCP infrastructure.

Cover line:

**Delivered by Absolute Health Group™ | Intelligence + Authority by AION™ | Governed Execution by GitHealth™**

## 4. The Four Rails

1. **Care Delivery** — assessments, pathways, care plans, training, navigation, monitoring and escalation.
2. **Coverage + Coding** — eligibility, CPT/HCPCS, ICD-10, NCD/LCD/billing articles, modifiers, place of service and documentation.
3. **CMS / Value-Based Payment** — FFS, CMS Innovation Center models, payer/VBC contracts and model-overlap controls.
4. **Proof + Economics** — eligibility, documentation, authorization, payment, remittance, outcomes and Cost-to-Goal™.

**A code is not coverage. Coverage is not payment. Payment is not proof. GitHealth connects all four.**

## 6. PIN + ACCESS Economics

| Economic dimension | PIN-in-a-Box™ | ACCESS Care-in-a-Box™ |
|---|---|---|
| Buyer | PCP / MSO / Senior Living | PCP / FQHC / RHC / Senior Living |
| Economic type | Recurring navigation | Co-management micro-workflow |
| Provider payment | Applicable PIN payment pathway | $30 reference CMP pathway |
| GitHealth monetization | Subscription + Workflow Units | Subscription + Workflow Units |
| Economic objective | Navigation contribution + scale | Low Cost-to-Goal + high-volume work |
| ROI | Recurring care-management ROI | Workflow ROI |

**Provider reimbursement ≠ GitHealth revenue.**

CMS lists ACCESS CMP G0676, G0677 and G0678 at a $30 allowed amount before applicable geographic and Medicare payment adjustments. The first qualifying CMP per beneficiary/track may include the AC modifier for an additional $10 when onboarding requirements are met. Verify current CMS requirements before billing.

PIN payment varies by code, locality, site of service and other Medicare payment factors. Use the applicable current fee schedule and coverage requirements rather than a synthetic 100-patient revenue case.

## 11. Brand Discipline

Do not create a new top-level software or care brand by default.

A new capability should normally become:
- an AION intelligence module;
- a PolicyPulse observation;
- a RegOS rule/control;
- a GitHealth Workflow Unit; or
- an application/module/workflow inside an existing Care-in-a-Box market-facing operating system.

A new top-level product should require a genuinely different buyer and purchasing decision.
