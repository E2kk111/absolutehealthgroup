# SurgicalOS™ / Surgery-in-a-Box™ — Proposed Care-in-a-Box Application

## Positioning
**One Surgical View. Connected Intelligence. Surgeon-Controlled Care.**

Proposed institutional specialty package to bring **live surgical video, navigation data and patient imaging** into a unified, surgeon-controlled workspace. SurgicalOS is an application of the existing Care-in-a-Box / GitHealth / AION architecture, not a new operating system or a claim of a working medical device.

## Proposed capabilities
1. Video input from approved, compatible OR/endoscopy/microscopy systems.
2. Navigation data from authorized surgical navigation systems, with explicit provenance and synchronization status.
3. Patient imaging from permitted imaging/PACS interfaces; confirm case/patient association and imaging orientation.
4. Multi-source display with data freshness, latency, source labels, loss-of-signal detection and manual fallback.
5. Authorized case event documentation, postoperative handoff and audit evidence.
6. Governed AI assistance, if separately validated, limited to defined intended use with surgeon review.

**Out of scope until validated:** automated instrument control, autonomous surgical decisions, unvalidated image registration, claims of real-time accuracy, FDA authorization, clinical outcome improvement, or hospital/ASC integrations.

## Pilot gate
- Define one procedure, one OR team, one site and compatible device inventory.
- Establish intended use, medical-device regulatory assessment and software quality/safety controls.
- Synthetic or appropriately de-identified recorded case demo before any live clinical use.
- Validate input compatibility, latency, synchronization, source identification, downtime behavior, cyber security, consent and privacy.
- Obtain hospital credentialing, surgeon and clinical engineering approval, risk/insurance review and device manufacturer permissions.
- Define prospective technical KPIs: display availability, end-to-end latency, frame drops, navigation synchronization, source misassociation, operator workload and incident reports.
- Never imply the product is clinically deployed or FDA cleared unless substantiated.

## Commercial and reimbursement
Potential commercial structure: one-time integration/implementation + facility/site license + approved workflow/evidence modules. No standalone CPT/HCPCS or Medicare reimbursement for this software is assumed. Clinician/facility reimbursement, if relevant, belongs to the actual eligible surgical services and must be assessed separately. Include professional liability, technology E&O, product liability and cyber risk in the insurance review; actual coverage depends on bound policies, exclusions and named insureds.

## Ecosystem
- **Absolute Health Group:** proposed clinical operating relationships and pilot facilitation.
- **GitHealth:** governed documentation, case workflows, quality/economic evidence.
- **AION:** rule evaluation, permissions, clinician authority, provenance.
- **Recovery Care-in-a-Box:** postoperative coordination, rehabilitation and measured recovery where applicable.

## Marketing boundary
This is a **proposed SurgicalOS concept**. The mockup on `/surgicalos` contains no patient data, live surgical video or connected navigation equipment.
